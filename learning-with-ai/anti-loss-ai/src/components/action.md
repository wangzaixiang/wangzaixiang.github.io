# 动作 / 交互组件

> 模板：职责 → 输入 → 输出 → 技术选型 → 训练要点 → 常见陷阱

## 职责

在**时间窗**上识别动作与手物交互，输出区间级事件：`scan_attempt`、`hand_holds`、`bagging` 等。它是把"物体轨迹"升级为"语义动作"的一层，当规则引擎无法用几何谓词覆盖时启用。

## 输入

按做法分两种模态，**这也决定了它是不是神经网络**：

- **结构化时序**（默认）：`track_id + box` 轨迹序列、关键点序列、ROI 掩码——低维、可解释。
- **像素片段**：一段视频 clip（RGB / 光流特征）——仅当"动作"依赖外观时才用。

## 输出

区间级事件（含起止时间与类别）：

```json
{ "t_start": 12.1, "t_end": 12.9, "type": "scan_attempt",
  "entities": { "hand": 7, "object": 42 }, "confidence": 0.88 }
```

## 技术选型：规则还是神经网络？

**取决于输入模态——默认不是神经网络。**

| 做法 | 输入模态 | 是否 NN | 适用 |
| --- | --- | --- | --- |
| **几何 / 时序规则** | 轨迹 + ROI | ❌ 否 | 进入/离开、停留、方向、接触——**首选** |
| 轨迹时序模型 | 轨迹特征序列 | ✅ 轻量（GRU / TCN / Transformer） | 规则写不出的轨迹模式 |
| 骨架动作识别 | 关键点序列 | ✅ 是（ST-GCN / PoseC3D） | 手 / 身体动作 |
| 视频动作识别 | **像素片段** | ✅ 是（X3D / TSM / UniFormer / VideoMAE） | 外观型动作 |
| HOI 检测 | 图像 + 手/物框 | ✅ 是（100DOH 系） | 手物交互 / 接触 |

> ⚠️ **模态要匹配**：视频动作模型（X3D / TSM / UniFormer / VideoMAE / ActionFormer）**吃的是像素片段，不是 `track_id + box`**——喂轨迹没有意义。反之，只有轨迹时，几何规则往往比 NN 更精确、更可解释、更可测。**能规则就别上模型**，NN 只在"规则覆盖不到的长尾动作"（如假扫）上引入。

## 训练要点

- **弱监督优先**：多数场景只有"这单有漏扫"的**视频级标签**，用 MIL（多示例学习）避免昂贵的区间标注。
- 数据集：Something-Something / Ego4D / 100DOH 做预训练，本店数据微调。
- 训练分布必须与部署帧率 / 时长一致（动作模型对采样率敏感）。

## 常见陷阱

1. **过度设计**：一上来就训动作识别，结果数据不够、收益不如规则。**先用规则。**
2. **时序对齐**：动作模型给的是区间，与 POS 事件对齐要考虑区间与瞬时点的映射。
3. **计算成本**：视频模型显著重于检测，端侧要谨慎；考虑降帧率、只在触发区做。
