# 手部关键点组件

> 模板：职责 → 输入 → 输出 → 技术选型 → 训练要点 → 常见陷阱

## 职责

提取手部的**关键点 / 姿态**，用于判断"手是否在扫描区""手是否接触商品""手的运动方向"。它是把"检测框"升级为"动作"的桥梁，让规则引擎能写出**几何谓词**而不是只靠物体轨迹。

## 输入

- 单帧图像，或由检测框裁剪出的手部 ROI。

## 输出

**帧级手部实体（不是事件）**：每只手输出手性、置信度、手部框与 21 个关键点。

```json
{
  "t": 12.345,
  "frame_id": 7412,
  "hands": [
    {
      "hand_id": 7,
      "handedness": "right",
      "score": 0.97,
      "bbox": [612, 340, 688, 455],
      "keypoints": [
        { "id": 0,  "name": "wrist",      "x": 655, "y": 452, "score": 0.99 },
        { "id": 4,  "name": "thumb_tip",  "x": 700, "y": 401, "score": 0.93 },
        { "id": 8,  "name": "index_tip",  "x": 712, "y": 388, "score": 0.90 },
        { "id": 12, "name": "middle_tip", "x": 706, "y": 377, "score": 0.88 }
      ],
      "keypoints_3d": null
    }
  ]
}
```

- `keypoints` 共 **21 点**，此处仅节选；坐标为图像像素、原点左上（也可另约定归一化到 $[0,1]$）。
- `hand_id` 由[跟踪](./tracking.md)组件补上；未接跟踪时省略。
- `keypoints_3d` 为**可选字段**（默认 `null`），取值见下。

### `keypoints_3d` 的取值

字段为 `null` 或一个对象；对象的含义由**坐标系 `frame`** 决定：

| `frame` | 语义 | 单位 / 原点 | 来源 | 需标定？ |
| --- | --- | --- | --- | --- |
| `wrist_relative` | 相对手腕的深度 | 归一化，量纲≈`x`；`z` 越小越近 | MediaPipe `multi_hand_landmarks` | 否 |
| `world` | 世界坐标（手自身） | **米**，原点≈手几何中心 | MediaPipe `multi_hand_world_landmarks` | 否 |
| `camera` | 相机坐标 | **米**，原点=相机 | 深度相机 / 多相机三角化 / 单目 3D | **是**（需标定或深度） |

```json
"keypoints_3d": {
  "frame": "wrist_relative",
  "unit": "image_width",
  "points": [
    { "id": 8, "name": "index_tip", "x": 0.09, "y": -0.02, "z": -0.05, "score": 0.90 }
  ]
}
```

每个点：`id`(0–20) · `name?` · `x, y, z` · `score?`。

也可输出更省的下游表示，而非裸 21×3：

| 表示 | 维度 | 用途 |
| --- | --- | --- |
| `pointing_dir`（食指根→尖的**单位向量**） | 3 | "食指指向条码" |
| `palm_normal`（掌心法向） | 3 | 手掌朝向 |
| 手势 / 抓握类别（`open` / `pinch` / `power_grasp`） | 1 | 粗略交互语义 |
| 参数化模型 MANO（`pose` θ, `shape` β） | 45 + 10 | 精细化 / 重定向 |

> **建议**：本场景大概率**用不到裸 3D 点**——"指向条码"只用一个派生方向向量，"手是否接触商品"用 2D 框交叠即可。故默认 `null`；确需深度时优先 `wrist_relative`（MediaPipe 免费给），别轻易上 `camera`（要标定 / 深度相机）。

### 21 点布局（MediaPipe 顺序）

| 索引 | 名称 | 部位 |
| --- | --- | --- |
| 0 | `wrist` | 手腕 |
| 1–4 | `thumb` CMC / MCP / IP / TIP | 拇指 |
| 5–8 | `index` MCP / PIP / DIP / TIP | 食指 |
| 9–12 | `middle` … | 中指 |
| 13–16 | `ring` … | 无名指 |
| 17–20 | `pinky` … | 小指 |

### 这个输出如何变成事件

帧级关键点 → 经[跟踪](./tracking.md)拿到稳定 `hand_id` → 与商品框做**接触判定** → 产出关系事件 `hand_holds(hand_id, item_id)`，供[规则引擎](./rule-engine.md)判定 `scan_attempt`（见[事件契约](../pipeline/contract.md)的 $\tau$ 枚举）。

## 技术选型

| 候选 | 特点 | 适用 |
| --- | --- | --- |
| **MediaPipe Hands** | 开箱即用的端侧手部关键点 / 追踪，速度极高 | **端侧首选 / MVP** |
| **RTMPose (MMPose)** | 精度高、可跨平台部署、配置灵活 | 需更高精度时 |
| 全身姿态（RTMPose / YOLO-Pose） | 加人体骨架 | 需要判断身体朝向 / 遮挡时 |

## 训练要点

- **优先用现成模型**：MediaPipe Hands 无需训练即可用于大多数几何谓词。
- 若需自训：用 100DOH 等手物交互数据集预训练，再在本店数据上微调。
- 关键点标注成本高；优先考虑"关键点 + 手部 box"的混合标注。

## 常见陷阱

1. **遮挡与快速运动**：手常被商品遮挡，关键点抖动大，下游要用**时序滤波**（如卡尔曼 / 滑动平均）。
2. **多手交叉**：自助收银可能双手同时操作，手性与 id 会串，需要与跟踪联合。
3. **过度依赖关键点**：很多判据用"手部 box + 物体轨迹"就够，不必上 21 点；先用低成本方案。
4. **手性约定**：MediaPipe 的 Left/Right 假定输入是**镜像（自拍）**画面；用非镜像相机时要**交换左右**，否则手性全反。
