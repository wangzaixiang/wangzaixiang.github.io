# 细粒度商品识别

> 模板：职责 → 输入 → 输出 → 技术选型 → 训练要点 → 常见陷阱

## 职责

识别商品的具体类别（SKU / 生鲜 PLU），用于与条码 / 录入 PLU 比对，解决 **banana trick（错扫）** 与 **ticket switching（换码）** 两类漏损。

## 输入

- 商品的裁剪图（来自检测框或轨迹的代表帧）；
- `cfg`：商品库 / SKU 目录 / 生鲜类别表。

## 输出

- 类别 + 置信度；
- 与 POS 录入的 PLU / SKU 的**一致性判定信号**（传给规则引擎）。

## 技术选型

| 候选 | 特点 | 适用 |
| --- | --- | --- |
| **ConvNeXt / EfficientNet** | 经典强分类 backbone | 闭集、有充足标注 |
| **CLIP / SigLIP embedding + 近邻检索** | 开放词汇，长尾友好，可零样本扩展 | **长尾商品首选** |
| 层次分类（粗类 → 细类） | 先分"肉/水产/果蔬"再细分 | 类别极多时 |

> 长尾是这里的根本约束：SKU 无穷无尽，纯闭集 softmax 必然崩。**用 embedding 检索 + 人工兜底**才能应对。

## 训练要点

- **长尾技巧**：focal loss、重采样、logit adjustment、解耦训练（backbone 与分类器分开）。
- **检索式方案**：用 CLIP 编商品库与现场裁剪图，比相似度；新品入库只需加 embedding，无需重训。
- **数据**：商品图可来自供应商图 + 现场拍摄；注意现场视角 / 光照与供应商图的域差。

## 常见陷阱

1. **闭集幻想**：以为能枚举所有 SKU。实际必须留开放集 / 人工兜底出口。
2. **域差**：供应商产品图 ≠ 收银台摄像头里的样子（角度、光照、包装反光）。
3. **与检测耦合**：裁剪质量差会拉垮分类，需保证上游检测框稳定。
4. **价格无关**：识别的是"是什么"，不是"多少钱"；计价逻辑仍由 POS 负责。
