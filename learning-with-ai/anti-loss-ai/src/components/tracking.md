# 跟踪组件（非神经网络）

> 模板：职责 → 输入 → 输出 → 技术选型 → 训练要点 → 常见陷阱

## 职责

把逐帧的检测结果**关联成跨帧轨迹**，为每个实体分配稳定的 `track_id`。它是 $f$ "有状态"的直接来源，也是把"帧级实体"变成"跨时间关系"的关键一步。

### 关联线索（如何判断是同一实体）

核心不是"比较 box 是否相等"，而是构造**代价矩阵 + 二分匹配**：先用运动模型把轨迹**预测**到当前帧，再与当前帧检测逐一算相似度。

| 线索 | 是什么 | 角色 | 代表方法 |
| --- | --- | --- | --- |
| 空间重叠 IoU | 预测框 ∩ 检测框 | **主** | SORT、ByteTrack |
| 运动一致性 | Kalman 预测的位置 / 速度 | **主**（产生预测框） | 全部 |
| 外观相似（ReID） | 检测框裁剪的 embedding 余弦距离 | **辅助 / 再关联** | DeepSORT、BoT-SORT、StrongSORT |
| 类别 | `class` 相同 | **门控**（hard gate），一般不入代价 | 多数仅作约束 |
| 形状 / 尺度 | 长宽比、面积 | 隐式（含在 IoU） | — |
| 检测分数 | 置信度高低 | 两阶段关联线索 | ByteTrack |

- **比的是"预测框 vs 检测框"**，不是"上一帧框 vs 这一帧框"——这正是需要 Kalman 的原因。
- **外观与运动互补**：外观给"像不像"，运动给"接不接得上"；只靠外观分不开同款商品，只靠运动扛不住高速 / 长遮挡。
- **`class` 只做门控**：防止把"手"配到"购物车"，但不作为相似度。

> 本场景同款商品多，外观几乎相同 → 以**运动为主**；MVP 用 ByteTrack 即可，只有当 id 切换真正伤害下游时才引入 ReID。

## 输入

- 检测组件输出的帧级实体（box + class + score）；
- 可选：手部关键点；
- 历史轨迹状态。

## 输出

稳定 id 的轨迹：

```json
[ { "track_id": 42, "class": "item", "trajectory": [ {t, box}, ... ] } ]
```

## 技术选型

| 候选 | 特点 |
| --- | --- |
| **ByteTrack** | 高低分检测结合关联，简单高效，工业首选 |
| **BoT-SORT** | 加入外观 + 相机运动补偿，更稳 |
| **OC-SORT** | 强调观测中心，抗遮挡 |
| ReID（**唯一需要训练的部件**） | OSNet / FastReID；用于跨窗 / 跨相机的 id 保持 |

> 跟踪**不是神经网络**：主体是 Kalman 滤波 + IoU / 外观代价的**数据关联**算法。"训练"主要是调参（关联阈值、寿命、匹配门限）。

## 训练要点

- 跟踪本身不训练；只有 ReID 分支需要训练（用行人 / 物体重识数据集 + 本店数据）。
- **轨迹标注可半自动**：用检测 + 关联规则自动生成轨迹，人工只修错。

## 常见陷阱

1. **id 切换（ID switch）**：遮挡、交叉、离开视野会导致 id 变化，破坏下游所有关联。
2. **短命目标**：快速掠过扫描窗的物体可能在检测上时断时续，跟踪要能"补"。
3. **滑窗重叠**：跨窗 id 一致性需要状态 $s$ 承载，否则每窗重置。
4. **把它当纯算法轻视**：跟踪质量往往比检测精度更影响最终事件质量。
