# 检测组件

> 模板：职责 → 输入 → 输出 → 技术选型 → 训练要点 → 常见陷阱

## 职责

在每一帧上定位**人、商品、（可选）购物车/篮**，为下游跟踪和交互判定提供实体观测。它是整条流水线**误差的源头**——检测一旦丢失目标，后面全都无从谈起。

## 输入

- 单帧图像（来自 $W_t$ 中采样的帧）。
- `cfg`：检测类别表、ROI（可选）、置信度阈值。

## 输出

帧级实体集合：

```json
[ { "class": "hand|person|item", "box": [x1,y1,x2,y2], "score": 0.93 } ]
```

- 只做**原子检测**，不做跨帧关联（那是跟踪组件的事）。
- 关键类（手、商品）需输出**较高的召回率**，宁可多报。

## 技术选型

| 候选 | 特点 | 适用 |
| --- | --- | --- |
| **YOLOv12 / YOLO26** | CNN+attention 实时检测，端侧友好，生态成熟 | **端侧首选**（nano/s 规模） |
| **RF-DETR** | DINOv2 backbone，迁移学习强，精度高但重 | 精度优先 / 离线 |
| **D-FINE / RT-DETR** | 端到端 Transformer 检测，无 NMS/锚框 | 中大型算力 |

选型锚点：**算力预算反推模型尺寸**。端侧盒（4 路、INT8、<1–2 s 延迟）通常只能跑 YOLO nano/s 级别。

## 训练要点

- **复用预训练**：YOLO/RF-DETR 均有 COCO 预训练权重，别从零训。
- **数据**：本店相机视角下的 box 标注；用"模型预标注 + 人工修正"做半自动标注。
- **类别设计**：手、人、商品（粗类）。细粒度识别交给[商品识别组件](./recognition.md)，**不要**在检测阶段就分 SKU。
- **增强**：光照、遮挡、视角抖动；以真实分布为主，别过度。
- **损失**：CIoU + DFL（YOLO 系标配）。

## 常见陷阱

1. **手部检测最容易被低估**：手小、运动快、常被商品遮挡，需要单独关注其召回率。
2. **类别不均衡**：商品类样本远多于手；用重采样 / focal 类技巧。
3. **跨相机泛化差**：不同视角 / 焦距的模型不能直接复用，需分别微调或做归一化。
4. **把检测当终点**：检测输出是"帧级实体"，不是"事件"。别指望检测器直接告诉你"漏扫"。
