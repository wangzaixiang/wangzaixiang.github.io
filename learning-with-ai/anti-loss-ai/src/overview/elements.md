# f 的要素逐条解读

对公式

$$
f_\theta:\ (W_t,\ \text{cfg},\ s) \longrightarrow \big(\,[\,(t_{event},\ \tau,\ X,\ p,\ \text{prov})\,],\ s'\,\big)
$$

逐一拆解每个要素。

## 1. $f$ 本身：它不是你熟悉的纯函数

| 性质 | 含义 | 工程后果 |
| --- | --- | --- |
| 概率性 / 多值 | 同一输入在不同权重 $\theta$ 下给不同输出 | 必须锁定**模型版本** |
| 有损 / 不可逆 | 从事件无法还原视频 | 事件是"投影"，不是"真值" |
| 病态 | 会**漏**（该报未报）会**误**（误报） | 需要召回率 / 误报率两个方向分别度量 |
| 稀疏 | 绝大多数窗口输出 `[]` | **空输出是正常且合法的** |
| 有状态 | `track_id` 跨窗保持 | 严格形式含状态 $s \to s'$ |
| 版本化 | $f = f_\theta$，换权重即换函数 | 公式中写作 $f_\theta$ |
| 因果性二选一 | 在线只看过去；离线可看未来 | 同一语义、**两套实现** |
| 有延迟 | 输出滞后于事件发生 | $t_{emit}-t_{event}$ 即延迟 |

> 把 $f$ 当纯函数会导致"相同输入 = 相同输出且总是对"的错误期望。正确期望是：**版本锁定、回放确定性、误漏可度量**。

## 2. $W_t$：输入的视频时间窗

- $t$：窗口锚点，在线场景通常取右端（=now）。
- $W$：窗口长度（秒或帧数），**最重要的超参**：太短看不到完整动作，太长则延迟高、算力高、噪声多。典型短动作 0.5–2 s，交互 / 会话级 3–10 s。
- 表示：不是原始帧堆叠，通常是"稀疏关键帧 + 邻近密集采样"的多尺度结构，或固定帧率下采样（如 10–15 fps）。
- 多视角：可以是集合 $\{(\text{cam}_1, W_t), (\text{cam}_2, W_t), \dots\}$——顶拍看手、侧拍看商品。
- 为什么不能是单帧：运动、手物交互、时序都是**非马尔可夫**的。

## 3. cfg：配置 / 标定 / 先验

| 类别 | 例子 | 变更频率 |
| --- | --- | --- |
| 相机标定 | 内参、外参、畸变 | 部署期 |
| 几何 ROI | 扫描窗多边形、打包区、货架区 | 部署期 |
| 类别体系 | 商品库 / SKU / 生鲜 PLU、检测类别表 | 周期性 |
| 策略阈值 | 触发阈值、干预策略、场景模式 | 运行期动态 |
| 运行时开关 | 自助 / 人工模式、相机选择 | 运行期动态 |

**关键点：cfg 是输入而不是常量，因为"语义"藏在几何里。** 同一段视频，把 ROI 从"扫描窗"改成"打包区"，输出完全不同。所以 $f$ 必须**每店、每相机**标定。

## 4. 外层 $[\cdot]$：输出是"流"

- 多重集 / 流，基数 $0..N$，稀疏。
- 有序：按 $t_{event}$ 排序；同刻多条需定义**稳定次序**（否则回放不可复现）。
- 在线无界、离线有界。
- 滑窗重叠会让同一事件被多次触发 → 需要 **dedup**。

## 5. $t_{event}$：事件时间

- 语义：事情**实际发生**的时刻，不是被检测到的时刻。
- 瞬时 vs 区间：动作有持续，严格应写成 $(t_{start}, t_{end})$ 或 $(t_{center}, \Delta)$。
- 单一时钟域：与 POS 对齐的前提（NTP/PTP）。
- 精度：检测本身受帧率限制（30 fps → ±33 ms），但要区分"事件真值精度"与"对齐分辨率"。
- **$t_{event}$ vs $t_{emit}$**：事件时间 vs 处理时间。实时干预看 $t_{emit}$，事后对齐看 $t_{event}$，两者之差即延迟。

## 6. $\tau$：事件类型（本体）

- 闭集且分层，建议分三层：实体层（`object_appears`）、关系/谓词层（`hand_holds`）、动作层（`scan_attempt`）。
- **判别式联合（discriminated union）**：$\tau$ 决定 $X$ 的结构。
- 必须版本化，与 $f_\theta$ 绑定。
- $\tau$ 的粒度直接决定下游状态机复杂度。

## 7. $X$：载荷

| 组成 | 例子 | 注意 |
| --- | --- | --- |
| 实体引用 | `track_id`、`class`、`box`、属性 | 引用完整性 |
| 关系 / 谓词 | `in_scan_window=true`、`motion=left_to_right` | 关系事件连两个实体 |
| 空间定位 | 像素 box / ROI 归属 / 世界坐标 | 供复核与存证 |
| 数量 / 属性 | 手持物数量、商品类别 | 细粒度识别的落点 |

$X$ 的结构**随 $\tau$ 变**；`track_id` 是 $f$ "有状态"的直接证据。

## 8. $p$：置信度——最容易被误用

- **$p$ 不是校准过的概率**，softmax 分数系统性偏高。
- 逐事件**边缘分**，联合分布不可得。
- 阈值由**业务代价函数**决定，绝不取 0.5：
  $$\tau^\* = \arg\min_\tau\ \big(\text{漏报代价}\cdot \text{FN}(\tau) + \text{误报代价}\cdot \text{FP}(\tau)\big)$$
- 如需真概率，用 temperature scaling / isotonic 校准；否则只用来做**排序**。

## 9. prov：溯源

模型版本 $\theta$、流水线组成、标定版本、cfg 引用、输入片段引用。用途：**可复现、漂移检测、回滚、审计、责任归属**。相当于日志里的 trace id + build id + config version。

## 10. 公式"没写但躲不掉"的四件事

1. **状态 $s$**：跟踪需要跨窗记忆，严格形式为 $f_\theta(W_t,\text{cfg},s)\to([\cdots],s')$。
2. **处理时间 $t_{emit}$ / 延迟**：实时性指标只有它能量化。
3. **实体 id 的稳定性**：跨窗、跨相机重识（re-ID）。
4. **幂等 / 去重**：滑窗重叠与重传导致重复事件。

## 11. 给公式配的"不变量"（可直接当测试用例）

| 不变量 | 断言 |
| --- | --- |
| Schema 合规 | 每条事件的 $\tau$ 与 $X$ 结构匹配 |
| 事件时间有序 | 输出按 $t_{event}$ 非降 |
| 会话内 id 持久 | 同一实体在一个 session 内 `track_id` 不复用给他人 |
| 回放确定性 | 固定 $f_\theta$ 与 cfg，同一段视频输出逐位一致 |
| 空输出合法 | `[]` 不是错误 |
| 状态可重放 | 从 $s_0$ 重放事件流可重建 $s$ |
