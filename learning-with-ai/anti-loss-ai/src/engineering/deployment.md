# 端侧部署与模型压缩

## 导出链

$$
\text{PyTorch} \to \text{ONNX} \to \text{TensorRT (INT8)}
$$

- **PTQ（训练后量化）**：快，适合多数场景；需代表性校准集。
- **QAT（量化感知训练）**：准，适合对精度敏感的关键层，代价是训练成本。

## 压缩手段

| 手段 | 作用 | 风险 |
| --- | --- | --- |
| **量化（INT8）** | 显存 / 带宽 / 速度大幅改善 | 精度损失，需校准 |
| **剪枝** | 去掉冗余通道 / 权重 | 结构化剪枝才在通用硬件加速 |
| **蒸馏** | 大模型教小模型 | 需要教师模型与足够数据 |
| **共享 backbone** | 多任务 / 多路复用 | 需要任务兼容 |

## 端侧推理与调度

- **异步调度**：感知（检测 + 关键点 + 跟踪）跑全帧率；动作 / 分类跑低帧率或仅在触发区。
- **批处理**：一拖四（单盒多路）时按路批处理，注意各路延迟公平。
- **流水线**：解码 → 推理 → 后处理（NMS / 关联）→ 事件合成，各阶段用线程池解耦。

## 延迟预算（示例，需按实际标定）

| 阶段 | 目标 |
| --- | --- |
| 采集 + 解码 | ~10–20 ms |
| 检测 + 关键点 | ~30–60 ms |
| 跟踪 + 后处理 | ~5–10 ms |
| 事件合成 | ~1–5 ms |
| **端到端** | **< 1–2 s（含窗口）** |

> 端到端延迟必须 < 干预的时间窗，否则提醒失去意义。窗口 $W$ 会直接叠加到延迟上——这是 $W$ 不能设太大的工程原因。

## 常见陷阱

1. **量化不做校准**：INT8 精度崩塌，尤其小目标（手）。
2. **忽略解码开销**：多路 RTSP 解码常被低估，需硬件解码。
3. **只看单帧延迟**：忘了窗口滞后带来的端到端延迟。
4. **没有降级路径**：模型或网络异常时应退化为"仅存证"，**绝不阻塞收银**。
