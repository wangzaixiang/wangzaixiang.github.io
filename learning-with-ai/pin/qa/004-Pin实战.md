# Q4: Pin 实战——什么场景需要手动使用 Pin？

## 问题

在日常 Rust 开发中，什么场景需要手动使用 Pin？请给出具体代码示例。

## 回答

### 好消息

大多数开发者不需要手动 Pin——`async fn` + `tokio::spawn` 已经内部处理了。

### 场景一：手写 `block_on` / 执行器

```rust
fn block_on<F: Future>(mut future: F) -> F::Output {
    let mut future = unsafe { Pin::new_unchecked(&mut future) };
    let waker = dummy_waker();
    let mut cx = Context::from_waker(&waker);
    loop {
        match future.as_mut().poll(&mut cx) {
            Poll::Ready(output) => return output,
            Poll::Pending => {}
        }
    }
}
```

- `unsafe` 是因为 `future` 可能 `!Unpin`
- `as_mut()` 是 Pin 的安全方法，重新借用不移动底层值

### 场景二：`select!` 多个 future

```rust
let mut f1 = Box::pin(async { /* ... */ });
let mut f2 = Box::pin(async { /* ... */ });

select! {
    result = f1.as_mut() => { /* f1 完成 */ }
    result = f2.as_mut() => { /* f2 完成 */ }
}
```

`select!` 需要同时持有多个 Future 的 `Pin<&mut Self>`。`Box::pin` 将每个 future 放到独立的堆地址上。

### 场景三：`stream!` / 异步迭代器

```rust
use futures::stream::{self, StreamExt};

let stream = stream::iter(vec![1, 2, 3]);
futures::pin_mut!(stream);

while let Some(item) = stream.next().await {
    println!("{}", item);
}
```

`Stream::next()` 的签名类似 `poll_next(self: Pin<&mut Self>, ...)`。

### 场景四：结构体存储 `!Unpin` Future

```rust
struct MyService {
    pending: Option<Pin<Box<dyn Future<Output = String> + Send>>>,
}

impl MyService {
    fn start_op(&mut self) {
        self.pending = Some(Box::pin(some_async_op()));
    }
}
```

`Box::pin` 将 future 放到堆上。移动结构体时只拷贝 `Pin<Box<T>>` 指针，`T` 不动。

### 检查清单

| 问题 | 回答 |
|---|---|
| 用 `async fn` + `tokio::spawn`？ | 不需要手动 Pin |
| 手写 `block_on`？ | 需要 `unsafe Pin::new_unchecked` |
| `select!` 多个 future？ | `Box::pin` 或 `pin!` + `as_mut()` |
| 结构体存储 `!Unpin` future？ | `Pin<Box<dyn Future>>` |
| 手写 `Future` impl？ | `pin_project` crate |
